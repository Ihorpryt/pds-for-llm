# Portside Design System — maintainer notes

## What this repo is for

Tokens, components and patterns for Portside internal products. Product managers use them
through the **Portside Prototypes** Claude skill to build interactive HTML prototypes that
engineers rebuild in production. Prototypes load the system from one published script,
`https://cdn.jsdelivr.net/npm/portside-pds@<version>/dist/psds.js`, pinned to a version.

Claude Desktop artifacts block stylesheets and fonts from CDNs but allow npm scripts from
jsDelivr. That is why everything ships as `psds.js`, which injects the CSS with the icon
fonts embedded. Don't switch prototypes to `<link>` tags.

## Where a change goes

| To change | Edit | Then also update |
| --- | --- | --- |
| How a component looks | `components/<name>/<name>.css` | its `.md` and `.html` example |
| A pattern (list page, modal) | `patterns/<name>/<name>.css` | its `.md`, and `starter/index.html` if it uses it |
| Colours, spacing, radii | `tokens.css` (light and dark blocks) | — |
| Interactive behaviour | `src/behaviour.js` | the Behaviour table in `guidance.md` |
| Rules the AI follows | `guidance.md` (single source of rules) | — |
| The skill's workflow | `skill/SKILL.md` (workflow only; rules stay in guidance.md) | — |
| The starting prototype | `starter/index.html` | its handoff notes at the top |

`dist/` is generated by `scripts/build.mjs` and `scripts/build-skill.mjs`; never edit it.

## Rules for changes

- **Don't rename or remove a class.** Published prototypes pin a version and keep working,
  but the skill and new prototypes would break. Add a new class and deprecate the old one in
  its `.md`.
- **Tokens only** in component CSS: no hex values or raw pixel sizes that a token covers.
- **New classes use the `psds-` prefix** and follow the component's BEM naming
  (`psds-modal__row`, `psds-btn--sm`). State helpers are `.is-*`.
- **Keep docs and the starter in step** with the CSS in the same change. `guidance.md`
  "Known gaps" lists what isn't solved yet; remove an entry when you fix it.
- **When a prototype review triggers the change**, look for the root cause in the system
  (missing class, unclear doc, psds.js bug) rather than patching one prototype. `proto-`
  classes listed under "Proposed additions" in a prototype's handoff notes are candidates
  for new components or pattern classes.

## Verify before committing

1. `npm run build:skill` (runs the bundle build first).
2. Preview with the `portside-static` server in `.claude/launch.json` (serves the repo
   root; it's local, not committed):
   - `starter/index.html`: open the modal, submit it empty (errors), fill it and save
     (new row and success toast); arrow through the dropdown; open the date picker. Check
     light and dark with `PSDS.setTheme('light' | 'dark')`, waiting for transitions to
     finish before screenshots.
   - The changed component's `.html` gallery page, in light and dark.
3. After changing `scripts/build.mjs` or anything about CSS load order: check that the
   bundle renders the same as the source stylesheets. Load each gallery page once as is
   and once with its `<link rel="stylesheet">` tags replaced by `dist/psds.js`, disable
   transitions, then compare `getComputedStyle` for every element and `::before` /
   `::after` in both themes. The expected result is zero differences.

## Release

1. Bump `version` in `package.json` (`0.1.0-beta.3`, …) and the `Design system:` line in
   the starter's handoff notes.
2. `npm run build:skill`, then commit and push.
3. The owner runs `npm publish --tag beta`. The npm account (`ihorpryt`) requires a
   security-key confirmation in the browser, so Claude can start the command but can't
   finish it.
4. Wait until `https://cdn.jsdelivr.net/npm/portside-pds@<version>/dist/psds.js` returns
   200 (usually 1–4 minutes).
5. The owner uploads `dist/portside-prototypes.zip` in Claude Desktop → Customize → Skills,
   replacing the existing skill.

Existing prototypes keep the version they were built with. To update one, ask Claude in
that prototype's chat to switch to the new version.
